## 확인한 원인
1. 원격 UI R19, R21의 V13 각 방 5·5·15·5 결과전 수신 영역은 이미 있었으나, 미수신 시 PNG가 없고 미수신 안내 위주라 빈 화면처럼 보일 수 있었음.
2. 항행의자유방(인덱스 9) 메뉴 이동 `pick(i)`가 **매번** `v13R19ShowFreedomFullscreen()`을 직접 호출해, V13 방별 결과전 화면 위에 V12 내장 V3 원본 전체화면 오버레이를 띄웠음.
3. 1248·1249회 원문 확보와 별개로 네 방의 진짜 정식 엔진 어댑터 및 검증된 결과전 보고서 수신이 미완결. 화면 표시 개선만으로 실제 5+5+15+5 번호를 만들어서는 안 됨.

## 수정 내역
- `pick(i)`의 항행의자유방 자동 오버레이 호출 제거. 메뉴를 누르면 **V13의 결과전 표시 영역**이 우선 나타남.
- 항행의자유방에 `V3 원본 전체화면 열기` 수동 버튼과 전용 클릭 핸들러 추가. 기존 V12 V3 MASTER iframe 경로, 닫기 버튼, 승인관리 버튼 및 보존 기록은 유지.
- `renderRoomResultSlots(roomKey,roundNo)` 읽기 전용 UI 함수 신설:
  - 선장방(5), 도사방(5), 항행의자유방(15: 원문5/자동A5/자동B5), 항해사방(5)
  - 수신 자료 없으면 **실제 번호 없음 / 0·5 또는 0·15** 표시. 난수나 추정 번호 없음.
  - 실제 보고서가 `acceptedRoomPredraw` 통과한 경우에만 수신 번호 표시하고, 출처 승인/최초등록/공식잠금은 별도로 표시함.
  - 기존 PNG 생성/저장, 정식 보고서 검증, 30조합 통합, 성적관리 원장 등은 유지.
- `fourRoomStatusDetails`에서 실제 수신 카운트를 5로 고정하는 표기 오류 수정: 항행의자유는 15로 표시.
- R21에 이미 연결된 1249회 원문 기준과 DB-1 UI 문구 일치: 1..1249 원본 읽기 전용, 새 원문 1250회부터.
- 원격 UI 문서 revision 22로 변경. **GitHub 공개 main, APK, 공개 manifest 또는 공지 변경 없음.**
