## 발견한 실제 동작 위험
- `v330PurchasePage`가 `R().analysis.auto20`만 읽어 구매 `buy.locked`에 보존된 조합과 불일치할 수 있었음.
- `storeAnalysisResult`는 `buy.locked` 상태에서도 `R().analysis`를 덮어쓸 수 있었음.
- 자동 20조합 생성 함수는 후보가 6~7개뿐이어도 동일한 조합을 반복 복사해 20개라고 표시할 수 있었음.

- 여러 순차 분석을 30초 제한 하나로 취소할 수 있어 시간 부족 가능성.

## 격리 패치
- `buy.locked`는 저장된 실제 `buy.auto20` 20개를 우선 표시. 값이 유효하지 않으면 보존된 최종 5조합만 보여주거나 HOLD; 새 번호를 꾸며내지 않음.
- 잠금된 회차 재분석에서 기존 `analysis`/구매기록을 덮어쓰지 않음. 추첨 후 별도 연구 저장 방식은 유지.
- 자동 20조합은 8개 이상의 고유 후보를 요구하며 서로 다른 20개를 얻지 못하면 생성 보류.
- 수동 원문이 6문장이 아니면 엔진 호출 전 차단. 엔진 iframe 이외 출처와 진행 세션 없는 응답은 무시.
- 4건 순차 엔진 분석을 고려해 타임아웃 60초로 완화하고 시간초과 시 엔진 재초기화.
- Node CI에서 잠금 화면, 저장 원본 불변, 중복 20조합 방지, 수동 6문장 검사, 외부 iframe 응답 차단을 추가 검증.
